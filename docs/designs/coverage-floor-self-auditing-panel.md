## Problem Statement

`docs/handoffs/coverage-floor.md` budgets ~3 hours to buy the "coverage floor": the
system must be able to answer a question in all eight key areas of the task brief, or
say honestly that it cannot. It ships three tasks — a `submarket_divergence` detector,
a minimal `macro_context` skill, and a coverage panel.

The doc was written before `app.py` existed and has drifted from the repo. Four of its
factual claims are now wrong, and Task 1's acceptance criteria cannot be satisfied by
Task 1's own thresholds. Meanwhile `docs/handoffs/watchlist-join.md` — which the
coverage doc itself names as "where the actual product value is" — is also unbuilt,
and the two documents overlap more than either admits.

Deadline is Sunday 2026-08-30 midnight. Slides and tests are deliberately deferred
until a rough MVP exists.

## What Makes This Cool

The coverage panel is normally the boring compliance item — a table someone writes by
hand, that is stale an hour later. Make it **computed** instead and it becomes the most
interesting thing in the repo.

The panel derives each area's status from `store.metrics()` and the `DETECTORS`
registry. It cannot claim coverage the code does not have, because it reads what is
actually wired. Delete a detector and its row flips back to `on request` on the next
run, with no one updating a table.

That is the project's P3 honesty discipline — every number carries its source, the
agent says what it does not know — made mechanical instead of asserted. It is also
three artifacts for the price of one: the answer to the brief's literal "eight key
areas" ask, a live scoreboard for the rest of the build, and a slide that is true
at the moment it is screenshotted.

### The verified defect

The Task 1 thresholds were implemented against the real seed and run. Result:

```
Hammersmith        22.0%   +1480 bps vs bench   ->  RISK          assets: []
VNEB               18.0%   +1080 bps            ->  RISK          assets: []
West End Core       4.4%    -280 bps, avg  -70  ->  OPPORTUNITY   Mayfair House
City Core           5.9%    -130 bps, avg -200  ->  OPPORTUNITY   120 Fenchurch St
City Fringe         8.0%     +80 bps, avg +150  ->  nothing       Clerkenwell Works
City                7.0%     -20 bps, avg  +10  ->  nothing       (both)
West End            null      n/a,    avg +190  ->  RISK          Mayfair House
```

Three consequences:

1. **City Fringe fires nothing.** +80 bps over benchmark (rule: >150) and `vs_avg`
   exactly +150 (rule: strictly >150). But acceptance demands "a City Fringe RISK
   signal naming Clerkenwell Works."
2. **The gotcha note is a trap.** It instructs the implementer to treat a missing
   City Fringe asset match as a broken submarket hierarchy. The hierarchy is correct:
   `matching(submarket="City Fringe")` returns `['Clerkenwell Works']`. Following the
   note costs an hour in `SubmarketIndex` chasing a bug that is not there.
3. **The 3-cap contradicts the warning above it.** The doc warns that Hammersmith and
   VNEB are not Central London core, then specifies a ranking rule that puts them
   first. The West End signal — null level, +190 bps, hits Mayfair House, and the exact
   case the doc writes a gotcha about — has undefined divergence and is truncated away.

### The corrected rules

- **RISK** — vacancy >150 bps above the Central London benchmark, **or** `vs_avg`
  **>= +150 bps** (`>=`, not `>`; this is what makes City Fringe fire and the doc's own
  acceptance criterion true).
- **OPPORTUNITY** — vacancy >100 bps below the benchmark **and** `vs_avg` negative.
- **Cap** — sort with the module's existing `Signal.sort_key()` (portfolio relevance
  first, then severity) and truncate. Do **not** rank by absolute divergence.

With an empty watchlist this correctly falls back to surfacing Hammersmith and VNEB,
which genuinely are the market-wide outliers. The empty-watchlist path stays complete,
which is a hard requirement.

### Design of the panel

New module `src/cre_agent/coverage.py`. One declarative table of intent, everything
else computed:

```python
@dataclass(frozen=True)
class KeyArea:
    n: int
    name: str
    metrics: tuple[str, ...]         # store metrics that serve this area
    detector: str | None = None      # must match a DETECTORS function __name__
    surfaced_by: str = "chat only"   # label when no detector serves it
    caveat: str | None = None        # honest gap, e.g. "no hybrid-working data in source"
```

Status is derived, never declared:

| Status | Derivation |
|---|---|
| `gap` | no declared metric present in `store.metrics()` |
| `on request` | data present, no detector registered — answerable in chat only |
| `partial` | detector registered but a `caveat` applies, or only some metrics present |
| `covered` | data present, detector registered in `DETECTORS`, and currently firing |

The honesty mechanism is that `KeyArea.detector` is resolved against
`{d.__name__ for d in DETECTORS}`, and firing is checked against live signal ids
(`Signal.id` is already `f"{detector}:{submarket}"`). Nothing to plumb into the
detectors themselves — the registry already carries what is needed, which makes this
cheaper than the 15 minutes originally estimated.

### Layout

Rendered as a Streamlit expander below the brief, collapsed by default so it never
competes with the ranked signals. No wireframe was generated: this is a table inside
Streamlit's fixed layout, its content is fully specified by the handoff, and design
variants would burn clock without changing the answer.


## Open Questions

1. **The cap should probably be 2, not 3.** With corrected thresholds and
   relevance-first ranking, `submarket_divergence` returns City Fringe RISK
   (Clerkenwell Works), West End RISK (Mayfair House) and City Core OPPORTUNITY
   (120 Fenchurch Street). Added to the three existing detectors, the front page
   reaches roughly seven signals. The MVP design deliberately surfaces about four,
   on the grounds that "eight equal tiles is a dashboard, which is the thing this
   product replaces." Recommendation: cap at 2. Alternative worth considering —
   emit one "vacancy divergence" signal carrying several submarkets as evidence,
   rather than one signal per submarket.
2. **Does macro survive the cut at all?** Its stated justification — "the clearest
   on-screen proof that this is an agent" — is already delivered by `app.py`, which
   streams every tool call in a live `st.status` panel, with Search grounding wired
   and verified. Judged only on its real payoff, the yield-versus-gilt spread, it
   needs one number (the 10-year gilt) rather than three, and becomes a ~20-minute
   job. If Sunday gets tight, this is the thing to cut; area 6 then renders `gap`
   honestly, which is a defensible outcome.
3. **`Signal.affected` as a structured match object.** Carried over from
   `watchlist-join.md`. Needed for "why did this asset match", but it touches every
   detector and the renderer. Decide before the lease-window work, not during.

## Success Criteria

1. The coverage panel renders all eight areas with a status derived from the registry,
   and at least two are `partial` or `gap`. Deleting a detector flips its row without
   anyone editing a table.
2. `detect_all(store, watchlist)` returns a City Fringe RISK signal naming Clerkenwell
   Works — the doc's own acceptance criterion, now reachable.
3. No signal renders a bps value with a `%` sign. Use `Delta.render()`.
4. Deleting every asset from `config/watchlist.yaml` leaves the market-wide brief
   complete. Hard requirement.
5. Two consecutive runs produce identical signals, headlines and figures.
6. If macro ships: asking "what's the Bank Rate?" returns a cited number, labelled as
   a live lookup and visually distinct from seed facts. With no network it says it
   cannot reach live data and does not invent a rate.
